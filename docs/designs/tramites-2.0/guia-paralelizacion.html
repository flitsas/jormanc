Reglas de oro

  1. Una HU ≈ un PR (máx. ~800 líneas).
  2. Orden: DDL → API → UI (nunca al revés).
  3. No mezclar schemas en el mismo PR sin acuerdo.
  4. Integrar a develop por olas, no acumular ramas.
  5. Mocks en DEV para Verifik/QX hasta que INT esté mergeado.
  6. Ramas: feature/AB-{huId}-descripcion · Commits: HU{id}: texto

Checklist antes del PR

  • Rama actualizada desde develop
  • feature/AB-{id}-descripcion
  • Migración probada localmente
  • Tests del módulo
  • PR < 800 líneas → develop
  • Descripción: HU #, tablas, deps mergeadas
